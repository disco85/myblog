* F*

There is a language [[https://fstar-lang.org/][F*]] used for safe, "proven" programming (similarly to [[https://leanprover.github.io/][LEAN]] but more
practice-oriented). It was used for real world applications like:

** HACL*, ValeCrypt, and EverCrypt

[[https://github.com/hacl-star/hacl-star/tree/main/vale][HACL*]] is a library of high-assurance cryptographic primitives, written in F* and extracted
to C. [[https://hacl-star.github.io/][ValeCrypt]] provides formally proven implementations of cryptographic primitives in
Vale, a framework for verified assembly language programming embedded in F*. EverCrypt
combines them into a single cryptographic provider. Code from these projects is now used
in production in several projects, including [[https://blog.mozilla.org/security/2017/09/13/verified-cryptography-firefox-57/][Mozilla Firefox]], [[https://github.com/torvalds/linux/blob/0f2a4af27b649c13ba76431552fe49c60120d0f6/lib/crypto/curve25519-hacl64.c#L1][the Linux kernel]], [[https://github.com/python/cpython/issues/99108][Python]],
mbedTLS, the [[https://www.reddit.com/r/tezos/comments/8hrsz2/tezos_switches_cryptographic_libraries_from/][Tezos blockchain]], the [[https://electionguard.vote/][ElectionGuard electronic voting SDK]], and the [[https://www.wireguard.com/][Wireguard VPN]].

** EverParse

[[https://project-everest.github.io/everparse/][EverParse]] is a parser generator for binary formats that produces C code extracted from
formally proven F*. Parsers from EverParse are used in production in several projects,
including in [[https://www.microsoft.com/en-us/research/blog/everparse-hardening-critical-attack-surfaces-with-formally-proven-message-parsers/][Windows Hyper-V]], where every network packet passing through the Azure cloud
platform is parsed and validated first by code generated by EverParse. EverParse is also
used in other production settings, including [[https://github.com/microsoft/ebpf-for-windows][ebpf-for-windows]].

* Installation and a simple project on Linux

** Installation

First, install F* with its dependencies in your ~$HOME~:

#+begin_src bash :eval no :exports code
curl -fsSL https://aka.ms/install-fstar | bash -s -- --release
#+end_src

Then build the missing library:

#+begin_src bash :eval no :exports code
cd ~/.local/fstar/lib/krml/dist/generic
# Check such line, it must exist:
grep -n "libkrmllib" Makefile.basic
# If yes, then let's build the library:
make -f Makefile.basic
# Now check that it was built:
ls -l libkrmllib.a
#+end_src

** Simple project

Create some a directory for your project. Then, inside it we should build a directory
structure like:

#+begin_example
p1/                        <-- this is my project's directory
├── Makefile
├── fstar/
│   └── Simple.fst
├── c/
│   └── main.c
└── build/
    ├── cache/
    └── out/
#+end_example

So:

#+begin_src bash :eval no :exports code
mkdir -p build/{cache,out}
mkdir c fstar
#+end_src

Put in ~fstar/~ folder a file ~Simple.fst~:

#+begin_src fstar :eval no :exports code
module Simple
open FStar.UInt32

let square (x:UInt32.t) : UInt32.t =
  x *%^ x
#+end_src

Put in ~c/main.c~ file this code:

#+begin_src c :eval no :exports code
#include <stdint.h>
#include <stdio.h>
#include "Simple.h"

int main(void)
{
    uint32_t x = 12;
    uint32_t y = Simple_square(x);
    printf("square(%u) = %u\n", x, y);
    return 0;
}
#+end_src

#+begin_src makefile :eval no :exports code
FSTAR := fstar.exe
KRML  := krml

BUILD := build
CACHE := $(BUILD)/cache
OUT   := $(BUILD)/out

FSTAR_SRC := fstar/Simple.fst
KRML_SRC  := $(OUT)/out.krml

.PHONY: all clean

all: $(BUILD)/demo

$(BUILD):
	mkdir -p $(BUILD)

$(CACHE):
	mkdir -p $(CACHE)

$(OUT):
	mkdir -p $(OUT)

# 1. Verify the F* module
$(CACHE)/Simple.fst.checked: $(FSTAR_SRC) | $(CACHE) $(OUT)
	$(FSTAR) \
		--cache_checked_modules \
		--cache_dir $(CACHE) \
		--odir $(OUT) \
		--ext fly_deps=false \
		$(FSTAR_SRC)

# 2. F* -> KaRaMeL .krml
$(KRML_SRC): $(CACHE)/Simple.fst.checked
	$(FSTAR) \
		--cache_checked_modules \
		--cache_dir $(CACHE) \
		--odir $(OUT) \
		--ext fly_deps=false \
		--codegen krml \
		$(FSTAR_SRC)

# 3. KaRaMeL -> C -> executable
$(BUILD)/demo: $(KRML_SRC) c/main.c
	$(KRML) \
		-tmpdir $(OUT) \
		$(KRML_SRC) \
		c/main.c \
		-o $(BUILD)/demo

clean:
	rm -rf $(BUILD)
#+end_src

Return to the project's directory and build the project with ~make~ command (just type
~make~). You will get now this structure:

#+begin_example
build
├── cache
│   └── Simple.fst.checked      <-- result of proving
├── demo*                       <-- executable file (from main.c)
└── out
    ├── compile_flags.txt
    ├── main.o
    ├── Makefile.basic
    ├── Makefile.include
    ├── out.krml
    ├── Simple.c                <-- generated C code
    ├── Simple.h                <-- C header file for API
    └── Simple.o
#+end_example

** What is it?

F* checked the code (well, current code is primitive kiddish code, nothing to prove there,
currently, but this is a skeleton only), then it used the result of checking and it
"extracted" (this is the term, not "translated") C code (~Simple.c~, ~Simple.h~) and,
finally, it called ~gcc~ compiler which produced ~demo~ binary file. It is small, 21752
bytes, because it's a result of usual C code compiled by ~gcc~.

The resulting extracted C code is also super-simple:

#+begin_src c :eval no :exports code
/*
  This file was generated by KaRaMeL <https://github.com/FStarLang/karamel>
  KaRaMeL invocation: krml -tmpdir build/out build/out/out.krml c/main.c -o build/demo
  F* version: <unknown>
  KaRaMeL version: 9abbb865b10a0cd5c557da81c024c3965cb6ff53
 */

#include "Simple.h"

uint32_t Simple_square(uint32_t x)
{
  return x * x;
}
#+end_src

It is not always so simple and plain, but usually it is. Actually, it depends on the
complexity of the input F* code.

The workflow is:

#+begin_example

                  Simple.fst
                      |
                      | F* verification
                      v
             Simple.fst.checked
                      |
                      | F* extraction
                      v
                  out.krml
                      |
                      | KaRaMeL
                      v
                Simple.c/.h
                      |
                      | GCC
                      v
                  demo
                      |
                      v
              square(12) = 144
#+end_example

~KaRaMeK~ is the "extractor", other extractions are also supported:

#+begin_quote
Various fragments of F* can also be extracted to F#, to C or Wasm by a tool called
KaRaMeL, or to assembly using the Vale toolchain. F* is implemented in F* and bootstrapped
using OCaml.
#+end_quote
