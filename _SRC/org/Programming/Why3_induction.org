* Proving by induction

There are different ways to prove something, in math one of them is proving by induction. Its
idea is: prove that a statement is true for every natural number ~n~.

- *Identify the cases.*
  The theorem, lemma, or claim usually has many cases. We want to prove that the statement is true for all of them.
- *Number the cases.* We describe the cases using a natural number ~n~.
  For example, if the cases are ~2x, 4x, 6x, 8x, ...~ we can describe the ~n~-th case as ~2*n*x~.
  So instead of proving infinitely many separate cases, we can talk about them using one number ~n~.
- *Prove the base case.* We prove that the statement is true for the first case, usually ~n=0~
  or ~n=1~ (it can be any ~n~ but it must be the first one).
- *Prove the induction step.* We prove a general rule:
  *I͟f͟ t͟h͟e͟ s͟t͟a͟t͟e͟m͟e͟n͟t͟ i͟s͟ t͟r͟u͟e͟ f͟o͟r͟ s͟o͟m͟e͟ c͟a͟s͟e͟ n͟,͟ t͟h͟e͟n͟ i͟t͟ i͟s͟ a͟l͟s͟o͟ t͟r͟u͟e͟ f͟o͟r͟ t͟h͟e͟ n͟e͟x͟t͟ c͟a͟s͟e͟,͟ n͟+͟1͟. And
  EVERY case has previous, next case, so it means ALL cases are true AFTER THE FIRST* ("next is true"
  automatically means "ALL" after some zero, initial case)
  The important word is some. We are not proving some case ~n=5~ leading to case ~n=6~. We prove
  the rule for every possible ~n~: ~P(n) => P(n+1)~
- *Put the two parts together.* We know the first case is true (let's say the first is ~n=1~):
  ~P(1)~ and we know that every true case leads to the next true case: ~P(n) => P(n+1)~. Therefore:
  ~P(1) => P(2) => P(3)...~
- So: *every case AFTER THE BASE CASE is true.*:

#+begin_example
P(1) => P(2)
P(2) => P(3)
P(3) => P(4)
...
P(n) => P(n+1)
#+end_example

#+begin_quote
PROVE THE FIRST CASE, THEN PROVE THAT EVERY CASE (IF IT IS TRUE) LEADS TO THE NEXT
CASE. THEREFORE ALL CASES AFTER THE BASE - ARE TRUE.
#+end_quote

Again, we don't prove that ~P(n)~ is true, we prove that *IF* ~P(n)~ is true, then ~P(n+1)~ is
true, but it does not prove that ~P(n)~ is true, maybe *IT IS NOT*. We prove only logical
connection between them - "IF one true, the next (any) true too" . But... if among them we see
at least one case true - then ALL are:

#+begin_example
          oh, true!
             |
            \v/ 
   ? -> ? -> O -> o -> ... -> o -> o -> o
            /|\   |
             |    |
            base  `-- if the previous is true
            case      then the next is true
#+end_example

What about cases BEFORE the first/BASE case? We don't know, maybe they are true, maybe no - look at
the implication logical function:

| U | V | U => V |
|---+---+--------|
| 0 | 0 |      1 |
| 0 | 1 |      1 |
| 1 | 0 |      0 |
| 1 | 1 |      1 |

and lets think that the base case is ~V~ and the previous one, unknown (?) - is ~U~. If ~V=1~ then
~U~ can be ~0~ and the implication (~=>~ or ~->~) will be true too. It means that if we proved
~P(n) => P(n+1)~ and if the base case if true (~1~), then there is only one case for the next
case - when both are true. But for the previous it is not true: ~0 => 1~ is true and if the base is
this ~1~ then the previous could be ~0~. So, the math. induction is based on the idea of the NEXT
cases only:

#+begin_quote
Mathematical induction is fundamentally about propagating truth from a starting point toward the
next cases: ~P(base-case) => P(base-case + 1) => P(base-case + 2) => ...~
#+end_quote

See [[https://en.wikipedia.org/wiki/Mathematical_induction][more in Wikipedia]].

* Induction in Why3

Lets prove this formula:

\begin{aligned}
P(n \in \mathbb{N}): 0 + 1 + 2 + \ldots + n = \sum_{i=1}^{n} i = \frac{n(n+1)}{2} \text{ , formula (1)}
\end{aligned}

It is proven by induction as...

/*Induction case*/ if want to prove that IF it is true for some ~n~ (some... hmmm, let's
call it ~k~, i.e., when ~n = k~), then it is true for the next (i.e., ~k + 1~). What do we
know? We know only that formula (1). We chose some PARTICULAR NUMBER among the series natural
numbers, we designed it as ~k~. The formula (not proven yet!) is the same (1) but imagine the
particular ~k~ instead of abstract ~n~. OK. The step is to prove that ~P(k+1)~ is true too -
when ~P(k)~ is true: ~P(k) => P(k+1)~. How? Look:

\begin{aligned}
\text{For k :   } 0 + 1 + \ldots + k = \frac{k(k+1)}{2} \\
\text{For the next, i.e., k + 1 is :   } 0 + 1 + \ldots + k + (k + 1) = ?
\end{aligned}

Well, ~?~ is our formula (1) plus this new addend - ~(k + 1)~:

\begin{aligned}
0 + 1 + \ldots + k + (k + 1) = \frac{k(k+1)}{2} + (k + 1)
\end{aligned}

After simplification this formula became:

\begin{aligned}
0 + 1 + \ldots + k + (k + 1) = \frac{(k+1)((k+1)+1)}{2}
\end{aligned}

If to rename ~(k + 1)~ as some... ~X~: $\frac{X(X+1)}{2}$, wow! We see again the formula (1) !
What is our conclusion after this mathematical exercise? It is:

#+begin_quote
If formula (1) is true (we don't know: maybe it is not!), but if (1) is true, for some /k/ then
it is true for /k+1/ too because IT IS THE SAME FORMULA AGAIN! So, we proved that if ~P(k)~ is
true then ~P(k + 1)~ will be true too.
#+end_quote

/*Base case*/ ok, now lets select the "base" case - ~n=0~ (or 1, etc):
   
\begin{aligned}
\text{Base case : }P(0) = \frac{0(0+1)}{2} = 0
\end{aligned}

#+begin_quote
Conclusion: Since both the base case and the induction step have been proved as true, by
mathematical induction the statement ~P(n)~ holds for every natural number ~n ≥ 0~ !
#+end_quote

Proven! This is the method, approach of math. induction - an example of its usage.

See [[https://en.wikipedia.org/wiki/Mathematical_induction#Sum_of_consecutive_natural_numbers][more on Wikipedia]].

How does it prove the formula (1) by induction?!

First, the "lemma" is our theorem, our formula (1). Second, it has "a contract": precondition,
postcondition and an argument ~n~:

#+begin_example
  requires { U(n) }       \_____  U(n) -> V(n): Assuming U(n), prove V(n).
  ensures { V(n) }        /
#+end_example

~U~ is ~n ≥ 0~. And the ~V~ is exactly $\frac{n(n+1)}{2}$ ! But... our lemma is not only
proposition-based, it has a body. And the body is this:

#+begin_example
    if n = 0 then
      ()
    else
      sum_formula (n - 1)
#+end_example

So, the base case is ~n=0~ - the lemma-with-a-body returns ~()~, i.e., a unit which means
"proven!", then - the induction step: else - follow recursion. By the way, this can be
rewritten lesser explicit and shorter, it is the same:

#+begin_example
    if n > 0 then
      sum_formula (n - 1)
#+end_example

What does Why3 do with all these? Using induction it has to check that ~P(n) => P(n+1)~ and to
find the base case. Our lemma is:

\begin{aligned}
P(n) \equiv \sum_{i=1}^{n} i = \frac{n(n+1)}{2}
\end{aligned}

~P(n-1)~ is, then:

\begin{aligned}
P(n - 1) \equiv \sum_{i=1}^{n - 1} i = \frac{(n-1)n}{2}
\end{aligned}

Two different propositions. We can assume $P(n - 1) = \sum_{i=1}^{n - 1} i$ as true - it will be our
/induction hypothesis/. Our goal is ~P(n)~ which is $\sum_{i=1}^{n} i = \frac{n(n+1)}{2}$ (the
postcondition of our lemma is).

From the recursive definition of the sum (~let rec function sum~) Why3 knows that when ~n > 0~:

\begin{aligned}
\sum_{i=1}^{n} i = n + \sum_{i=1}^{n - 1} i
\end{aligned}

and Why3 use it in our goal ~P(n)~, replacing $\sum_{i=1}^{n} i$ by $n + \sum_{i=1}^{n - 1} i$ :

\begin{aligned}
n + \sum_{i=1}^{n - 1} i = \frac{n(n + 1)}{2}
\end{aligned}

Why3 uses the $\sum_{i=1}^{n - 1} i$ from the induction hypothesis and:

\begin{aligned}
n + \frac{(n - 1)n}{2} = \frac{n(n + 1)}{2}
\end{aligned}

This is passed to SMT solver and it easy proves it (~n~ is in a numerical domain - a task as for SMT).

Conceptually, the induction step is ~P(n - 1) => P(n)~, but Why3 doesn't necessarily hand Z3
one giant formula literally written in this way. Instead, Why3 creates a /verification
condition/ (VC) with ~P(n - 1)~ as an assumption $P(n-1) \vdash P(n)$ which means:

#+begin_quote
Assuming ~P(n - 1)~ as true, prove ~P(n)~
#+end_quote

*** Why does not Why3 prove P(n-1) case?

When Why3 sees that some goal (a lemma in the case) is *recursive* and *it has a variant*
(decreasing measure) it "think" in this way:

I (Why3) sees:

#+begin_example
let rec lemma foo (n: int)         GOAL:       P(n)
  ensures { P(n) }                 -----
  variant { n }                    AVAILABLE:  P(n-1)
=                                  ----------    :
  if n = 0 then ()                               :
  else foo (n-1)               From recursive call/SPECIFICATION
#+end_example

Why3 doesn't recursively open another proof obligation saying "now prove P(n-1)". *It uses the
induction mechanism instead.*

But if we write:

#+begin_example
let lemma bar (n: int)
  ensures { P(n-1) }
=
  ...without recursive call supplying P(n-1), and no variant too
#+end_example

then the goal is plain ~P(n-1)~ from ~ensures {..}~. And Why3 in this case will prove ~P(n-1)~.
When Why3 sees induction, it proves the base case, and then proves the connection/IMPLICATION
between ~P(n) => P(n+1)~ - it is "smart" enough. To do it Why3 needs:

- recursion
- variant (decreasing measure)

When Why3 sees something like: ~foo(smaller_argument)~ then what does the ensures clause of
~foo~ give it? If it gives Why3: ~P(smaller_argument)~ then Why3 can use that as an induction
hypothesis while proving the current invocation.

#+begin_quote
The ~variant~ answers a different question:

    Why am I allowed to use the recursive call?

Answer:

    Because the recursive argument/measure is smaller.
#+end_quote

*Why3 proves ~P(n-1)~ when ~P(n-1)~ is the current verification goal; it ASSUMES/uses ~P(n-1)~
when a valid recursive call to a lemma whose CONTRACT (~ensures {..}~) guarantees ~P(n-1)~ is
available while proving P(n).*

** Transformations

What are transformations in Why3?

A transformation rewrites a proof goal into one or more new goals, usually in a predictable,
logic-level way. In Why3, a transformation might introduce an implication’s premises as hypotheses,
split a conjunction, or simplify a formula. It generally doesn’t construct a proof by itself; it
changes the task that a prover must solve.

Why3 transformations are typically reusable goal-to-goal operations, often used to prepare
verification conditions for automated provers.

"Reusable" means that you can save them in a session file if you applied them interactively in IDE
(as commands: IDE has an edit box for typing of "commands"). Also you can pass them as options in
command line as ~--apply-transform~ - one by one.

A transformation can resemble a simple "tactic": for instance, Why3’s introduce_premises is similar
in effect to introducing assumptions in Rocq or LEAN. But tactics are a broader mechanism and can
include search, branching, and proof construction.

Transformations are best thought of as goal transformations; tactics are proof-state programs. The
boundary isn’t absolute—some tactics merely transform goals, and some systems expose transformations
through tactic-like interfaces.

Transformation is REWRITING of the initial WhyML happening "in the memory".

Simple example: ~split_vc~ splits a verification condition into separate goals, typically by
decomposing a top-level conjunction in the goal.  For example, a goal ~P /\ Q~ becomes 2 goals, ~P~
and ~Q~. This *lets Why3 send each obligation to SMT prover separately*. It *does not prove them*;
it *restructures the proof task*. I.e., ~split_vc~ is a transformation: it takes a verification
condition and produces separate proof goals, rather than proving them itself. If you think that
it looks as an "optimization" then yes - it affects the performance of the proving and if you has hit
timeout or similar, then sometimes ~split_vc~ can help.

Usually you use transformations exactly for this: you cannot prove some goal, using transformations
you solve this problem. Well, sometimes you need rewriting of WhyML too... anyway, this is the idea
of "transformations".

You can see all supported transformations by the simple command:

*** What is "inductive" ?

Why3 supports "predicate" - something returning true or false. The construction using the keyword
~inductive~ means "define this predicate by rules" (~sum_def~). It has 2 arguments:

#+begin_example
sum_def : int -> int -> Prop
#+end_example

and when it is used as ~sum_def 3 6~ then it is a PROPOSITION, saying "6 is the sum associated with
3."

And because it is an inductive predicate, you don't define it with a Boolean expression such as
~predicate sum_def (n,s:int) = ...~. Instead, you define *RULES FOR CONSTRUCTING PROOFS OF
IT*. Yes, the CONSTRUCTORS ARE RULES FOR PROVING THE PREDICATE:

#+begin_example
                                 sum_def n s
   ───────────              ─────────────────────
   sum_def 0 0              sum_def (n+1) (s+n+1)

#+end_example

#+begin_quote
If you already have a proof that ~sum_def n s~, you are allowed to construct a proof that
~sum_def (n+1) (s+n+1)~.
#+end_quote

this is the *induction step*:

#+begin_quote
THE WORD I͟N͟D͟U͟C͟T͟I͟V͟E͟ MEANS THAT *THE PREDICATE IS DEFINED BY HOW ITS PROOFS CAN BE CONSTRUCTED FROM EARLIER PROOFS*.
#+end_quote

#+begin_example
        Zero
sum_def 0 0
      ↓ More
sum_def 1 1
      ↓ More
sum_def 2 3
      ↓ More
sum_def 3 6
      ↓ More
sum_def 4 10
#+end_example

And the surprise part is that if to try to prove it with Why3, then it will... timeout! And it can
be overcome with the help of transformations.

 The thing you need is exactly:

```
induction_arg_pr H with_gen n,s
```

 The `with_gen` part is the important piece.

 Why3 1.8.x added this optional argument specifically to control which variables are generalized
 during induction. The Why3 examples themselves use the syntax `induction_arg_pr H with_gen x,y`.
 Why3+1

 ## Why your previous induction was bad

 You currently have:

```
constant n : int
constant s : int

H1 : sum_def n s

H :
  ((s + n) + 1) = s ->
  (n + 1) = n ->
  ...
```

 Why3 has kept the **outer** `n` and `s` fixed while constructing the induction
 hypothesis. Consequently, the induction hypothesis says, roughly:

 > "If the new values happen to equal the old values, then the formula holds."

 That's useless.

 What we want is to say:

 > "For **any** `n` and `s`, if `sum_def n s`, then the formula holds."

 So we need to **generalize `n` and `s`** during the induction.

 ## Do this

 Starting with:

```
lemma sum_formula:
  forall n s: int.
    sum_def n s ->
    2 * s = n * (n + 1)
```

 ### 1\. `introduce_premises`

 Run:

```
introduce_premises
```

 You get roughly:

```

constant s : int
H1 : sum_def n s

Goal:
  2 * s = n * (n + 1)
```

 ### 2\. Induct on `H1`, generalizing `n,s`

 Run:

```
induction_arg_pr H1 with_gen n,s
```

 **This is the important command.**

 Now Why3 should generate the induction hypothesis in the useful form.

 You should get a base case roughly like:

```
s = 0
n = 0

Goal:
2 * s = n * (n + 1)
```

 which Z3 can solve.

 And the `More` case should be roughly:

```
n : int
s : int

H1 : sum_def n s

H :
  2 * s = n * (n + 1)

Goal:
  2 * (s + n + 1) =
    (n + 1) * ((n + 1) + 1)
```

 **That `H` is exactly the induction hypothesis we wanted.**

 Then Z3 should be able to prove the arithmetic.

 ## Why `with_gen n,s` fixes it

 Think about the mathematical induction you're trying to express.

 You want to prove:

 $$
\forall n,s,\quad
sum\_def(n,s)\rightarrow P(n,s)
$$

 where

 $$
P(n,s)\equiv 2s=n(n+1).
$$

 The induction principle needs to be:

 ### Zero

 $$
P(0,0)
$$

 ### More

 $$
\boxed{P(n,s)\Rightarrow P(n+1,s+n+1)}
$$

 The crucial part is that the $n,s$ in $P(n,s)$ are **arbitrary**.

 That's what `with_gen n,s` tells Why3:

 > Don't freeze the current `n` and `s`; generalize them so that the induction hypothesis can apply
 to the predecessor's `n1,s1`.

 This is precisely the purpose of the `with_gen` option.  Why3
